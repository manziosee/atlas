# ADR-0003: API authentication — TLS 1.3, bearer tokens, optional mTLS

- **Status:** Accepted
- **Date:** 2026-10-18

## Context

The HTTP API exposes cluster topology. It must be safe by default, simple to
use from the CLI and CI, and stricter in production.

## Decision

- **TLS 1.3 only** for the API; production refuses to start without TLS unless
  `ATLAS_TLS_TERMINATED_UPSTREAM=true` declares a trusted terminating proxy.
- **Bearer tokens** (≥ 32 chars, generated by `atlas-cli tokengen`), stored as
  SHA-256 digests and compared in constant time against *all* tokens. A list
  of tokens enables rotation.
- **Optional mTLS** (`ATLAS_TLS_CLIENT_AUTH=true`) for zero-trust setups.
- Certificates **hot-reload** from disk so short-lived certs (cert-manager,
  Vault) rotate without restarts.
- Health endpoints stay unauthenticated so orchestrators can probe them; they
  reveal nothing beyond liveness.

## Consequences

- ✅ Secure defaults; misconfiguration fails at startup, not in production.
- ⚠️ Static tokens have no per-user identity or expiry. OIDC/JWT is a
  candidate once a dashboard with users exists.

## Alternatives considered

- **JWT now:** needs an issuer and key distribution, which is premature.
- **mTLS only:** strongest, but painful for ad-hoc CLI use; kept optional.
